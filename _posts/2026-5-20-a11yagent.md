[a11yagent](https://marketplace.visualstudio.com/items?itemName=IDEA.a11yagent) is a VS Code extension designed to help screen reader users discover accessibility features and troubleshoot accessibility-related issues within VS Code. It provides an interactive chat participant that can answer questions, search for relevant issues, and track updates related to accessibility issues in VS Code.

## Background

### Discoverability in IDEs
IDEs have feature-rich GUIs. Existing research shows that Blind, Low-Vision, and Visually Impaired (BLVI) developers often struggle to find and learn about these features, given that many of these features have visual indicators. BLVI developers often rely on social forums, documentation, and trial-and-error methods to discover and learn about features.

In order to study ways of improving discoverability within IDEs, we focused on VS Code - the most widely used developer environment per the 2025 Developer Survey by Stack Overflow.

### Accessibility in VS Code
VS Code offers several built-in features specifically designed to support BLVI developers. As of Version 1.116 (release date: April 15, 2026), VS Code has 73 accessibility-related settings in the settings editor alone, ranging from keyboard shortcuts and audio cues to alternate interface views to support screen reader use.

GitHub Copilot, the popular AI-based programming assistant integrated with VS Code, is now commonly used for various programming tasks like code generation and editing, acting like a peer programmer. Copilot could, in theory, act as an AI peer who provides guidance for using various IDE features within VS Code while programming. However, in practice, Copilot frequently provides inadequate responses when asked about accessibility features in VS Code. Its answers are often UI-based, even when the IDE is used in its ‘screen-reader optimized’ mode.

## Formative Research

### How have accessibility features changed over time in VS Code?

To understand the evolution of these features, we analyzed VS Code’s official monthly release notes over the past 4.5 years (January 2021 to June 2025). The general trend indicated 2 to 5 accessibility-related features being introduced or changed every month, with some months having as many as 11 changes.

### What queries do users have about about Features in VS Code?

To understand the kinds of issues faced by BLVI  developers in discovering and utilizing features in VS Code, we coded and analyzed queries posted by BLVI users about VS Code features on program-l for the past 5 years (from January 2021 to December 2025). 

These posts indicated several discoverability challenges faced by users. Users felt overwhelmed by the abundance of features and their evolving behavior and were unsure about which features met their specific requirements, if any. Users frequently asked about the meaning of specific sound cues, the keybindings required to complete particular workflows, and reported issues encountered in trying to use specific features within VS Code. Queries were more frequent for some features, like the Accessible View and Copilot suggestions. 

## Introducing a11yagent

Drawing upon the insights from the aforementioned analysis, we built an AI-based accessibility assistant designed to assist BLVI developers in discovering and utilizing the features of VS Code - a11yagent. a11yagent uses accessibility-specific data extracted from various sources, including the official VS Code documentation, release notes, settings, default keybindings, signals/announcements, VS Code repos, and telemetry logs (if enabled) to answer user queries. It uses the same language models that GitHub Copilot uses, but the answers it generates are grounded using accessibility-specific data sources as context and a detailed system prompt so that they are more relevant for screen reader users.

### Features

#### Accessibility chat participant
Users can ask accessibility-related questions (how to use specific settings, what accessibility features of VS Code might be helpful for a particular workflow, how to fix an issue they are facing in using a feature, etc.) by invoking the agent with @a11yagent. They can also ask follow-up questions if the initial response doesn't fully address their query.

#### Accessibility issue search
Users can describe an issue they are facing in VS Code to a11yagent, and it'll run a GitHub search to look up and return any matching GitHub issues related to VS Code.
The generated response will contain a list of relevant issues, possible workarounds mentioned in the discussions, and timelines or plans for addressing the issue if present.

Users can then choose to track any of these issues to receive updates when they are being worked on/resolved. If the returned issues don't match their needs, they can choose to log their description so that a11yagent can notify them if relevant issues are found in the future.
